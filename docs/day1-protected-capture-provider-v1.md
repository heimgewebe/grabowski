# Day-1 protected capture provider — prototype v1

**Status: source-only, disabled, not deployed, not eligible for productive admission.** Owner: [Grabowski #1387](https://github.com/heimgewebe/grabowski/issues/1387). Consumers: [heim-pc #197](https://github.com/heimgewebe/heim-pc/pull/197) (blocked), [#199](https://github.com/heimgewebe/heim-pc/issues/199) (protected Evidence/Consumer), [#198](https://github.com/heimgewebe/heim-pc/issues/198) (render-time evidence). Companion [Grabowski #1389](https://github.com/heimgewebe/grabowski/pull/1389) is an offline signed-proof verifier; [#1388](https://github.com/heimgewebe/grabowski/pull/1388) explicitly refuses Day-1 admission.

## What has been implemented

`tools/day1_protected_capture_provider.py` implements a *separate*, root-only, one-shot **actual capture/signing parent**. It does not use Grabowski's generic `systemd-root-broker`, does not introduce a new MCP callable, and does not allow an arbitrary executable, argv, shell, user-defined signing namespace or destination. The matching systemd unit is an **uninstalled `.example` with no `[Install]`/timer and `RefuseManualStart=yes`**.

Its exact control surface, which must be installed only through a separately approved trusted deployment, is:

| Root-only source | Purpose |
|---|---|
| `/etc/grabowski/day1-capture-policy-v1.json` | Root-owned bounded canonical policy, not task UID writable |
| `/usr/local/libexec/grabowski/day1-collector-static` | Fixed root-owned **static ELF64 x86-64 ET_EXEC**; pinned exact SHA-256 in policy |
| `/etc/grabowski/day1-capture-signing-key` | Root-owned `0600` dedicated SSH Ed25519 key, **never stored in Git** |
| `/usr/local/libexec/grabowski/day1-ssh-keygen-static` | **NOT INSTALLED**; reviewed static ELF64 signer without PT_INTERP/PT_DYNAMIC; SHA-256 pinned in policy and invoked via its retained FD |
| `/var/lib/grabowski/day1-capture` | Existing root-owned `0700` evidence root |
| `grabowski-day1-collector` | Dedicated non-login, non-root system account with no other untrusted workloads |

All source/config/key path ancestors must be root-owned and not group/world writable. Symlinked ancestors/leaves, ambiguous inodes, non-regular/multiply linked files, unsafe modes, changed identity during source read and missing/oversize source bytes are rejected. The root-only parent validates the policy host against `socket.gethostname()`. No user-specified path or command is accepted.

**The real file must be canonical compact UTF-8 sorted-key JSON with a final LF**, not this indented documentation example. The placeholders above are deliberately not usable. All real bytes must come from the separately approved root-owned installation; no signing key, account, program or policy was created by this PR.

### Physical execution boundary

1. The root parent opens and SHA-256-verifies the **actual root-owned executable FD**, not merely a user repository path. It requires a fixed static ELF64 x86-64 ET_EXEC binary **with no PT_INTERP or PT_DYNAMIC** (so no runtime dynamic library/loader or Python imports). It is never a shell/script. The reviewed build must establish and retain the exact binary/source binding. This is usable on the existing Pop!_OS host; there is no false dependency on having NixOS installed first.
2. The separately named dedicated collector process starts through `execve("/proc/self/fd/<opened-collector-fd>")`. That inherited descriptor names exactly the inode the root parent previously read and hashed. The parent drops the child to a dedicated UID and **a canonical dedicated primary GID distinct from the operator's primary and supplementary GIDs**, clears all child supplementary groups, and passes the verified ELF FD with only the required redirected standard streams. Neither the operator UID nor the dedicated collector UID can rewrite the root-owned code or root parent's buffers.
3. The root parent reads **both child pipes directly** via bounded nonblocking descriptors. Output overflow, nonzero exit, missing EOF, unexpected child/pipe failure or timeout **prevents signing and authoritative publication**. It terminates the process group on failures. The uninstalled template explicitly pins `Slice=system.slice`, `TasksAccounting=yes`, `TasksMax=2` (root parent + one child task) and `ProtectControlGroups=yes`. The source parent now **refuses capture or signing** unless its kernel `/proc/self/cgroup` names exactly the fixed system unit and root-owned, descriptor-opened cgroup v2 controls report **`pids.max=2`, `pids.current=1`, and `cgroup.procs` containing only the parent PID**, checked before child launch, after collector exit and after signing. `pids.current` accounts for nested child cgroups and threads, unlike a primary-PID or pipe-EOF check. With this policy enforced, an additional fork/clone is denied, while an existing survivor prevents signing. `KillMode=control-group` remains the unit-level stop boundary. This does **not** prevent same-PID secondary `execve`, establish the source→binary closure, or demonstrate actual physical-host cgroup/protection. Deployment and admission are still blocked. No truncated stream is promoted as complete.
4. Only after the **primary process exits zero and stdout/stderr reach EOF** is one **signed, non-admitting prototype receipt** built. It contains a fresh **capture ID (not Grabowski task ID)**, initial opened executable SHA-256, **claimed** source revision from root policy, observed stream hashes/lengths and parent-observed capture/primary exit times. The signed `grabowski.day1_capture_prototype_not_admitted` kind explicitly marks `execution_closure_verified=false`, `actual_task_binding_verified=false`, `collector_process_tree_verified=false`, `day1_admission_authorized=false`. It does **not** sign `state=completed` or a fabricated `grabowski-task-*.service`. The root-owned key and signer executable are kept open via checked FDs throughout signing; the signer must be the separately staged root-owned **static ELF64 ET_EXEC without PT_INTERP/PT_DYNAMIC**, SHA-256-pinned in policy, with both FDs rechecked after signing. The ordinary dynamically linked `/usr/bin/ssh-keygen` is rejected in productive source. No reviewed static signer is installed. Positive **synthetic** SSHSIG tests explicitly mock only this static-signer requirement to exercise disposable Ed25519 test signatures using distro OpenSSH; those tests do not establish privileged signer execution. Its namespace is **`grabowski-day1-capture-prototype-v1@heimgewebe`**, deliberately distinct from the real-task verifier #1389. **#1389 must reject this prototype even when its SSH signature is cryptographically valid.**
5. Root-only staging holds `stdout.bin`, `stderr.bin`, `proof.json` and `proof.sshsig`. Each file is create-only `0600`, read back and `fsync`ed, then the containing `0700` directory is atomically renamed from `.incomplete-...` to **`prototype-<capture-id>-<nonce>`** under the root-owned parent directory and the parent directory is `fsync`ed. These directories are **never authoritative task proofs**. A root-owned create-only canonical `.capture-attempt-v1.json` now reserves one independent **prototype capture ID and nonce** before collector execution, binds host, policy SHA-256 and initial executable SHA-256, and fsyncs the reservation and parent directory. An existing reservation (including a crash before/after rename), noncanonical/symlinked/mismatching reservation, ambiguous fsync or an orphaned staged/published directory **blocks reissuance and execution**, even if a previous prototype appears successful. This is an intentionally **single-shot non-admitting reservation**, not a Grabowski task/attempt issuer, automatic recovery, signed final task proof or authenticated retry. A separate `tools/day1_protected_capture_attempts.py` now offers **read-only, fail-closed prototype material classification**: a pinned root-owned reservation and staged/published directory are checked with no-follow file descriptors, exact leaf names, identity/hash/size consistency, signed `false` fields and bounded SSHSIG *framing*. It never verifies the signature, claims transaction durability, resolves a failed attempt, launches a retry or upgrades admission. The only positive-looking label means `published_prototype_bytes_consistent_signature_unverified`, **not** authenticated output or a completed task. Authoritative protected readback/recovery and a stable external task authority remain unresolved. There is no mutable `current` symlink and no retroactive v2 receipt signing.

## Residual security and integration gates (not claims)

The policy's `source_revision` must be independently checked against a reproducible, reviewed binary build; a root-owned binary SHA does **not** prove that it implements the same semantics as the Python software-inventory collector. The first disposable/static test collector emits only fixture bytes; it is **not** the final Day-1 host software/program inventory contract. A reviewed, static/fully immutable equivalent of the real host collector, with verified data-access scope and no unpinned subprocess helpers, is still required. **Rejecting PT_INTERP/PT_DYNAMIC is insufficient to exclude secondary `execve` calls, static libc runtime loading, or a different program replacing the collector process.** A disposable adversarial test builds two static ELF binaries: the policy-pinned first binary invokes `execve` of the second without forking. The parent captures bytes from the **second binary**, and a genuine disposable SSH signature verifies, but the signed receipt still explicitly has `execution_closure_verified=false` and `day1_admission_authorized=false`. This demonstrates the missing closure protection; it is **not** a production fix, root-owned host test or admitted proof. No kernel-enforced child-exec prohibition or proven transitive executable closure is implemented in this draft. A real admission must independently close that gap through source/build verification and, where required, execution confinement; the current proof is not an independently authenticated full code closure.

The signed prototype has **no `task_id`, `unit`, `executed_source_sha256` or `execution_closure_sha256` fields**. It uses `capture_id` and identifies its inert parent template separately, without claiming a real Grabowski `systemd-user` task. **The task lifecycle/nonce issuance, full child-process-tree termination and canonical v2 outcome receipt binding demanded by #1387 are not yet integrated**. They must be independently audited before any non-prototype Day-1 proof use. There is no claim of completed real host inventory, trusted runtime activation, or approved `current_binding`.

The signing key and verified **static** signer executable descriptors remain pinned during signing, but the provider does not install a static signer, rotate keys or publish its **root-owned allowed signers** policy, nor register/enable the #1389 reader. The reader #1389 intentionally rejects the different non-admitting prototype kind and namespace. A protected consumer that verifies *the original root-owned four-file bundle* (not a user-modifiable copied file or past checked mutable pointer) remains for [heim-pc #199](https://github.com/heimgewebe/heim-pc/issues/199). A successful signature of real pipes would prove only that this **independent dedicated collector** ran its reviewed binary; it does not automatically authenticate legacy `stdout.log`, mutable SQLite, or other user-UID tasks.

## Acceptance before installing/activating

- Before any root-key use, reproducibly build and independently review a working **static signer** without PT_INTERP/PT_DYNAMIC and with complete build/helper/source closure evidence. The default dynamically linked `/usr/bin/ssh-keygen` cannot satisfy this requirement. Package/install all root-owned paths **from frozen reviewed source** with rollback evidence, isolated source/package and private key custody; confirm path ancestors/inode/UID/mode via independent Observer. No policy edit or deployment in this PR.
- Create the dedicated no-login system UID/GID through a separately reviewed host provisioning contract. Prove its UID and canonical primary GID are disjoint from Grabowski controller UID, primary GID and **all supplementary groups**, and not shared with any attacker workload; confirm effective/saved UID/GID/no supplementary groups **at actual execution**.
- Independently observe on physical `heim-pc`: exact opened collector binary hash/inode, direct pipe full bytes, child/parent UIDs, protected key, signature check using a distinct root-pinned verifier authority, terminal unit/task ID and crash/retry-proof protected readback.
- Negative attacks must swap same-UID `stdout.log`, SQLite, lifecycle self-hash, source file, policy path, signer/key FD, shared controller group, and post-terminal output; inject symlinks/races, forged signing key, replay nonce, truncated/overlong output, failed child and crash during/after rename; each must be rejected or left explicitly ineligible. Kernel-enforced prevention/tracking of descendant processes and secondary `execve`, plus stable upstream task IDs and post-rename readback reconciliation, are **not implemented** and must gate any real task proof.
- Bind actual protected task proof to Grabowski terminal receipts and to [heim-pc #197](https://github.com/heimgewebe/heim-pc/pull/197)'s admission predicate with **separate** review, exact-head tests and Captain gates; retain `current_binding=null` until host evidence is fully authenticated.

**Test-only simulation warning:** Synthetic tests may replace root-ownership checks with user-owned temporary directories, omit UID dropping and **mock only the static-signer requirement in positive SSHSIG fixtures** to exercise disposable signatures with a dynamically linked distro `ssh-keygen`. A separate negative regression verifies that the real source denies PT_INTERP signers. This is never a production fallback. Those tests validate algorithm/data-integrity paths but are **not** privileged execution evidence. Until a real root-owned deployment/observer readback exists, this code is not sufficient to close #1387 or merge #197.

## Operational status and rollback

No root-owned config, key, binary, system UID, systemd unit, timer, broker policy, actual current host state or NixOS storage/boot state has been modified. No `[Install]` section exists. Rollback of this source-only change is a regular code revert; the existing Grabowski task backend and v2 receipt schema are untouched. Any later operational pilot requires an explicitly approved root-managed install, exact unit/host preflight and reverse-operation plan.
